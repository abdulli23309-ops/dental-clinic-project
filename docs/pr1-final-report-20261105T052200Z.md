## 2. Authorization Model & Invariants

The clinic system enforces strict branch-scoped clinical authorization:
$$\text{DoctorServices}(\text{doctor}, \text{branch}) \subseteq \text{BranchServices}(\text{branch})$$

- **Branch Services:** Maintained in `clinic_services(clinic_id, service_id)`.
- **Doctor Branch Authorization:** Maintained in `service_providers(team_member_id, service_id, clinic_id)`.
- **Branch Clinician Assignment:** Doctor must be affiliated with the branch via `team_members.clinic_id == clinic_id` OR `team_member_clinics(team_member_id, clinic_id, is_active=True)`.
- **Enforcement Rules:**
  - `POST /api/v1/appointments` (public wizard) rejects any booking attempt for a doctor not explicitly authorized for that service at that specific branch with `409 Conflict`.
  - `POST /api/v1/reception/appointments` (reception desk) validates the same authorization chain with `409 Conflict`.
  - Auto-assignment (when no doctor is pre-selected) checks that at least one authorized doctor is affiliated with the branch, selecting only from doctors authorized for that service at that branch.
  - Setting service providers requires a non-NULL `clinic_id: UUID` and verifies that the branch offers the service in `clinic_services` with `is_active=True`, raising `422 Unprocessable Entity` if not offered.

### 5.2 Application Layer & Multi-Branch Doctor Lookup Fix
- **Bug Identified:** When a patient booked without specifying a doctor, `AppointmentService` checked `TeamMemberORM.clinic_id == clinic_id`. If a doctor belonged to multiple branches via `team_member_clinics`, but had a primary `clinic_id` pointing to another branch or `NULL`, the booking was erroneously rejected with 409.
- **Fix Implemented:** In both `AppointmentService` and `ReceptionService`, clinician branch assignment checks were updated to join `TeamMemberClinicORM`:
  ```python
  assigned = await self._session.execute(
      select(TeamMemberORM.id)
      .outerjoin(
          TeamMemberClinicORM,
          (TeamMemberClinicORM.team_member_id == TeamMemberORM.id)
          & (TeamMemberClinicORM.clinic_id == clinic_id)
          & (TeamMemberClinicORM.is_active.is_(True)),
      )
      .where(
          TeamMemberORM.is_active.is_(True),
          TeamMemberORM.id.in_(list(eligible_ids)),
          or_(
              TeamMemberORM.clinic_id == clinic_id,
              TeamMemberClinicORM.id.is_not(None),
          ),
      )
  )
  if assigned.first() is None:
      ...
  ```
- **Multiple Doctor Fix:** Replaced `assigned.scalar_one_or_none()` with `assigned.first() is None` to prevent `MultipleResultsFound` exceptions when more than one authorized doctor is assigned to a branch.

### 5.3 Audit Logging on Rejections
In both `ReceptionService.create_booking` and `AppointmentService.create_appointment_request`, whenever a booking is rejected due to branch-service-doctor scope failure:
```python
async def _log_scope_rejection(
    self,
    clinic_id: Optional[UUID],
    service_id: Optional[str],
    team_member_id: Optional[UUID],
    reason: str,
    source: str = "public",
) -> None:
    try:
        session = self._session
        if session is not None:
            log_entry = ActivityLogORM(
                id=uuid4(),
                user_id=None,
                user_email="system@booking",
                user_role="system",
                action="booking_rejected_service_scope",
                resource_type="booking",
                resource_id=f"scope-reject-{uuid4().hex[:8]}",
                details={
                    "service_id": str(service_id) if service_id else None,
                    "team_member_id": str(team_member_id) if team_member_id else None,
                    "clinic_id": str(clinic_id) if clinic_id else None,
                    "reason": reason,
                    "source": source,
                },
                ip_address=None,
            )
            session.add(log_entry)
            await session.commit()
    except Exception as exc:
        logger.warning(f"Failed to record booking rejection audit log: {exc}")
```
- **Zero PHI:** Patient name, email, phone, notes, and clinical details are never included in the log entry.
- **Fail-Safe:** Wrapped in `try...except`; audit log persistence failure never converts a rejection into a success.
